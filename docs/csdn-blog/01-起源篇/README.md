### 3. 《为什么选择 Electron？—— 一次纠结的技术选型》

**关键词**：技术选型、Electron、跨平台

**内容大纲**：
```markdown
## 选型困境
- Web 应用 vs 桌面应用
- Electron vs Tauri vs Flutter
- 开发效率 vs 性能
- 生态完善度

## Electron 的优势
- ✅ 跨平台：一次开发，三端运行
- ✅ Web 技术栈：Vue/React 熟悉
- ✅ 生态成熟：VS Code、Slack 都在用
- ✅ Node.js 集成：SSH 库丰富

## Electron 的劣势
- ❌ 包体积大（100MB+）
- ❌ 内存占用高
- ❌ 启动速度慢

## 为什么最终选择 Electron
- 开发效率优先（个人项目）
- SSH 功能需要系统级能力
- 需要访问本地文件系统
- Web 应用限制太多

## 其他方案的考虑
- Tauri：Rust 学习成本高
- Flutter：生态还不够成熟
- 原生开发：成本太高

## 总结
- 没有完美的技术选型
- 选择适合自己的
- 技术选型的思考框架
```

**发布时间**：第 2 周

**推广要点**：
- 技术对比详细
- 给出决策依据
- 适合技术决策者阅读

### 5. 《从想法到产品：AI SSH Assistant 的产品设计思考》

**关键词**：产品设计、用户体验、功能规划

**内容大纲**：
```markdown
## 产品定位
- 不只是工具，而是助手
- 目标用户：运维、后端开发、DevOps
- 使用场景分析

## 核心功能设计
- AI 对话：自然语言交互
- SSH 管理：连接管理、安全存储
- 终端模拟：完整的 SSH 功能
- 文件管理：SFTP 文件传输

## UX 设计考虑
- 参考 VS Code 的界面设计
- 侧边栏 + 主内容区布局
- 暗色主题（程序员最爱）
- 快捷键支持

## 功能取舍
- 要做：AI 对话、SSH、文件管理
- 不做：服务器监控、日志分析（暂时）
- 为什么？MVP 原则

## 用户体验细节
- 连接状态实时显示
- 命令执行风险提示
- 操作日志记录
- 错误友好提示

## 总结
- 好的产品需要设计
- 从用户角度思考
- 持续迭代优化
```
