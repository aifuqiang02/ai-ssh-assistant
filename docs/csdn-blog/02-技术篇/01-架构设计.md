## 前言

Assistant 从想法到产品的过程。现在，让我们深入技术层面，看看这个项目是如何架构的。

### 为什么选择 Monorepo？

**优势**：

1. ✅ **代码复用** - 共享类型、工具函数
2. ✅ **统一管理** - 统一的依赖版本
3. ✅ **原子提交** - 跨包修改一次提交
4. ✅ **类型安全** - 跨包的类型推导

**劣势**：

1. ❌ **构建复杂** - 需要处理包依赖
2. ❌ **学习成本** - 需要理解 workspace
3. ❌ **CI/CD 复杂** - 需要智能构建

**为什么选择 pnpm？**

- 🚀 **速度快** - 比 npm/yarn 快 2-3 倍
- 💾 **节省空间** - 硬链接共享依赖
- 🔒 **严格** - 不会提升依赖，避免幽灵依赖

## 设计原则

### 1. 关注点分离

**原则**：每个模块只关注自己的职责。

**实践**：

- 前端只负责 UI 和交互
- 后端只负责业务逻辑和数据
- 数据库层只负责数据持久化

**好处**：

- 代码清晰
- 易于测试
- 易于维护

### 2. 可测试性

**原则**：代码应该易于测试。

**实践**：

- 依赖注入
- 接口抽象
- 单一职责

**示例**：

```typescript
// 不好的设计
class SSHService {
  async connect(config: SSHConfig) {
    const client = new Client() // 硬编码依赖
    // ...
  }
}

// 好的设计
interface ISSHClient {
  connect(config: SSHConfig): Promise<void>
  execute(command: string): Promise<string>
}

class SSHService {
  constructor(private client: ISSHClient) {} // 依赖注入

  async connect(config: SSHConfig) {
    await this.client.connect(config)
  }
}

// 测试时可以注入 Mock
const mockClient: ISSHClient = {
  connect: jest.fn(),
  execute: jest.fn()
}
const service = new SSHService(mockClient)
```

### 3. 可扩展性

**原则**：系统应该易于扩展。

**实践**：

- 插件系统
- 事件驱动
- 策略模式

**示例**：

```typescript
// AI 服务的可扩展设计
interface AIProvider {
  name: string
  chat(messages: ChatMessage[]): Promise<string>
}

class OpenAIProvider implements AIProvider {
  name = 'OpenAI'
  async chat(messages: ChatMessage[]) {
    // OpenAI 实现
  }
}

class ClaudeProvider implements AIProvider {
  name = 'Claude'
  async chat(messages: ChatMessage[]) {
    // Claude 实现
  }
}

class AIService {
  private providers: Map<string, AIProvider> = new Map()

  registerProvider(provider: AIProvider) {
    this.providers.set(provider.name, provider)
  }

  async chat(providerName: string, messages: ChatMessage[]) {
    const provider = this.providers.get(providerName)
    if (!provider) throw new Error(`Provider ${providerName} not found`)
    return provider.chat(messages)
  }
}
```

### 4. 代码复用

**原则**：避免重复代码。

**实践**：

- 共享类型（packages/shared）
- 共享工具函数
- 组件复用

**示例**：

```typescript
// packages/shared/src/utils/validation.ts
export function validateSSHConfig(config: SSHConnectionConfig): string[] {
  const errors: string[] = []

  if (!config.host) errors.push('Host is required')
  if (config.port < 1 || config.port > 65535) errors.push('Invalid port')
  if (!config.username) errors.push('Username is required')

  return errors
}

// 前端和后端都可以使用
import { validateSSHConfig } from '@ai-ssh-assistant/shared'

const errors = validateSSHConfig(config)
if (errors.length > 0) {
  // 处理错误
}
```
